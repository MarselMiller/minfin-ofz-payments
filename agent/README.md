# Агент: выплаты по ОФЗ за любой период, три метода и сверка

- **Что делает.** По сообщению в чате с ИИ собирает купоны, погашения и частичные погашения ОФЗ с сайта Минфина за указанный период тремя методами (скрытое API, HTML, браузер), сверяет их и, только если они совпали строка в строку, кладет CSV и отчет в `data_files/` в корне репозитория. Колонки те же, что в итоговом `ofz_payments_2024_2026.csv`.
- **Какой ИИ подойдет.** Любой ИИ-ассистент, который умеет выполнять команды в папке проекта (Python), имеет доступ к minfin.gov.ru и может запустить Chromium через Playwright, например Claude Code на твоем компьютере. В песочнице чата (claude.ai и т.п.) сайт обычно закрыт: там ИИ сможет объяснить и поправить код, но собрать данные не сможет и скажет об этом. Git не обязателен: без него файлы просто остаются в `data_files/`.
- **Как начать.** В корне репозитория лежит `AGENTS.md`, который многие ИИ-инструменты читают сами, поэтому обычно хватает фразы вроде «запусти агента по сбору данных с сайта Минфина». Надежнее всего написать явно, например:

  > Прочитай agent/AGENTS.md и следуй ему. Собери выплаты ОФЗ с 2025-03-01 по 2025-06-30.

- **Что будет дальше:**
  1. Если в запросе чего-то не хватает (например, нет точных дат), ИИ спросит.
  2. ИИ попросит разрешение на 1 запрос к сайту для подсчета. Разрешаем словом **ЗАПУСК**.
  3. ИИ покажет, сколько сообщений (до N: лента берется с запасом по дате публикации) и сколько займет сбор каждым методом, и снова попросит **ЗАПУСК**.
  4. Методы работают по очереди и независимо: если один упал, остальные все равно прогоняются, а в ответе видно, что с каждым. Если результат есть у всех трех, они сверяются. Только ответ сайта 503 останавливает сбор целиком.
  5. Если все три отработали без проблем и совпали: файлы `data_files/ofz_payments_<с>_<по>.csv` и `report_<с>_<по>.md`, коммит в текущей ветке, короткая сводка в чате.
  6. Техническую поломку ИИ чинит сам и рассказывает, что поменял. Смысловую проблему (новый вид платежа, не сходится «Итого», методы разошлись, у сообщения нет docx и т.п.) выносит на решение со статусом каждого метода и списком вариантов. Пока проблема не решена, итогового файла нет.
- **Устройство.** Код сбора, разбора и сверки не продублирован: `collect.py` выполняет ячейки тетрадей `01_api`, `02_html`, `03_browser` и затем `04_compare`, а вместо первой ячейки с датами подставляет свой период. Починка метода делается в его тетради, и агент сразу работает по исправленному коду. `test_collect.py` проверяет разбор всех трех методов на файлах четырех сообщений из `agent/fixtures/` без обращения к сайту.
- **Служебные папки, в git не попадают.** `agent/cache/` хранит скачанное методами API и HTML: страницы ленты, docx и страницы сообщений. У браузера кэша нет, он каждый раз открывает страницы заново. `agent/work/<с>_<по>/` хранит промежуточные CSV методов: после успешной сверки папка удаляется, при проблеме остается, пока ее не решат.
- **Пересборка без сайта.** После технической починки ИИ запускает `run --offline`: HTML и API пересобираются из кэша, браузер берет свой результат прошлого прогона. Если чинили сам браузер или чего-то не хватает в кэше, команда остановится с кодом 3, и ИИ попросит **ЗАПУСК**.
- **Скорость.** HTML и API: около 1,7 с на запрос, но страницы, уже скачанные в `01_api/raw/`, `02_html/raw/` и в кэш агента, повторно не запрашиваются. Браузер: около 3 с на страницу, всегда все страницы периода. Месяц обычно занимает меньше минуты, 2024-2026 целиком 10-15 минут при первом запуске и около 8 при повторном.
- **Ручной запуск без ИИ:**
  ```
  python agent/collect.py count --from 2025-03-01 --to 2025-06-30
  python agent/collect.py run   --from 2025-03-01 --to 2025-06-30
  python agent/collect.py run   --from 2025-03-01 --to 2025-06-30 --offline   # без сайта: после починки
  python agent/test_collect.py
  ```
  Для браузера нужен Chromium: `python -m playwright install chromium` или путь к готовому Chromium в переменной `CHROMIUM_PATH`.
